# Chinook SQL Project – Music Store Sales & Customer Analysis

## 📌 Project Overview

This project uses SQL to analyze music store revenue, customer spending, country-wise sales, artist performance, album sales, and music genre popularity using the Chinook database.

The main objective is to understand sales performance, identify valuable customers, compare revenue across countries and music genres, and explore employee support performance using SQL queries.

## 📊 Dataset Used

**Dataset:** Chinook Database

**Source:** https://github.com/lerocha/chinook-database

**Version:** 1.4.5

**Script:** `Chinook_MySql.sql`

The Chinook database contains information about a digital music store, including customers, employees, invoices, purchased tracks, albums, artists, and genres.

### Main Tables Used

| Table         | Description                                           |
| ------------- | ----------------------------------------------------- |
| `Customer`    | Customer details and country information              |
| `Invoice`     | Invoice dates, billing countries, and total amounts   |
| `InvoiceLine` | Purchased tracks, quantities, and unit prices         |
| `Track`       | Track names, prices, and album/genre relationships    |
| `Genre`       | Music genre information                               |
| `Artist`      | Artist details                                        |
| `Album`       | Album information associated with artists             |
| `Employee`    | Employee details and customer support representatives |

## 🧠 SQL Concepts Used

### 1. Database Commands

* `SHOW DATABASES` to display available databases.
* `USE` to select the Chinook database.
* `SHOW TABLES` to display the tables in the selected database.

### 2. JOIN Operations

Joins combine related information from multiple tables.

Examples:

* `Customer` with `Invoice`
* `Artist` with `Album`
* `Album` with `Track`
* `Track` with `InvoiceLine`
* `Genre` with `Track`
* `Employee` with customer spending information

### 3. Aggregate Functions

| Function  | Purpose                                                     |
| --------- | ----------------------------------------------------------- |
| `SUM()`   | Calculate total revenue, spending, and purchased quantities |
| `COUNT()` | Count customers, tracks, and records                        |
| `AVG()`   | Calculate average customer spending and customer value      |
| `ROUND()` | Round revenue and spending values                           |
| `MAX()`   | Find the latest date or highest value when required         |

### 4. GROUP BY and ORDER BY

* `GROUP BY` groups records by country, customer, artist, album, genre, employee, or year.
* `ORDER BY` sorts results to identify the highest revenue, spending, and purchase quantities.
* `LIMIT` restricts results, such as displaying the top 10 customers or top 20 tracks and artists.

### 5. Window Functions

The project uses window functions for ranking and revenue calculations.

| Function                   | Purpose                                                            |
| -------------------------- | ------------------------------------------------------------------ |
| `RANK()`                   | Rank customers by total spending                                   |
| `SUM() OVER()`             | Calculate total revenue across grouped country results             |
| `PARTITION BY`             | Can divide window calculations into separate groups when specified |
| `ORDER BY` inside `OVER()` | Defines the ordering of window calculations                        |

### 6. Common Table Expressions (CTEs)

The `WITH` clause creates a named temporary result set.

A CTE is used to calculate customer spending and connect customers with their assigned support representatives to analyze employee performance.

### 7. Subqueries

A subquery calculates total spending for each customer before finding the average customer spending across the customer base.

### 8. CASE Expression

The `CASE` expression classifies customers based on total spending.

| Spending           | Customer Segment |
| ------------------ | ---------------- |
| 40 or more         | High Value       |
| 20 to less than 40 | Medium Value     |
| Below 20           | Low Value        |

These thresholds are the classification rules defined in this project.

### 9. Date Functions

* `YEAR()` extracts the year from an invoice date.
* Grouping by year allows yearly revenue comparisons.
* `ORDER BY` arranges yearly revenue results chronologically.

### 10. Revenue Calculations

The project calculates revenue using invoice totals and invoice-line quantities and prices.

**Revenue Percentage**

`Country Revenue / Total Revenue × 100`

Invoice-line revenue is calculated as:

`Unit Price × Quantity`

These calculations support country-wise revenue contribution, artist revenue, album sales, and genre revenue analysis.

## 🔍 Key Findings and Insights

The queries are designed to investigate the following areas:

1. **Overall sales performance:** Total invoice revenue provides an overview of the store's recorded sales.
2. **Country-wise revenue:** Grouping invoice totals by billing country helps identify the countries contributing the most revenue.
3. **Customer value:** Customer spending calculations identify the highest-spending customers and show differences in customer value.
4. **Average spending:** Average customer spending provides a reference point for understanding customer purchasing value.
5. **Customer segmentation:** Spending-based categories divide customers into high-, medium-, and low-value segments.
6. **Artist performance:** Revenue calculations identify artists whose tracks generate the most sales.
7. **Genre popularity:** Purchased quantities reveal which genres receive the most purchases, while revenue calculations compare their financial contributions.
8. **Album and track performance:** Album sales and track purchase quantities help identify popular music products.
9. **Employee performance:** Aggregating customer spending by support representative helps compare the revenue associated with their purchasing customers.
10. **Yearly revenue trends:** Grouping invoice totals by year helps compare recorded sales across years.
11. **Customer purchase activity:** Identifying customers without invoices helps distinguish customers who have never purchased from those who have made purchases.

*Note: These are the analytical areas investigated by the SQL queries. Exact customer names, revenue amounts, rankings, and other findings should be reported using the actual query outputs.*
