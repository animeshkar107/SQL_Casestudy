# Chinook SQL Project – Customer Segmentation & Music Store Revenue Analysis

## 📌 Project Overview

This project uses SQL to analyze customer spending, purchasing behavior, music preferences, artist revenue, and sales trends using the Chinook database.

The main objective is to understand customer value, identify popular music genres and tracks, analyze revenue contributions, and discover purchasing patterns using SQL queries.

## 📊 Dataset Used

**Dataset:** Chinook Database
**Source:** https://github.com/lerocha/chinook-database 
**Version:** 1.4.5
**Script:** Chinook_MySql.sql

The Chinook database contains information about a digital music store, including customers, invoices, invoice line items, tracks, albums, artists, and genres.

### Main Tables Used

| Table         | Description                                        |
| ------------- | -------------------------------------------------- |
| `Customer`    | Customer information and country                   |
| `Invoice`     | Customer invoices, dates, and total amounts        |
| `InvoiceLine` | Purchased tracks, quantities, and unit prices      |
| `Track`       | Track names, prices, and genre/album relationships |
| `Genre`       | Music genre information                            |
| `Artist`      | Artist details                                     |
| `Album`       | Album information associated with artists          |

## 🧠 SQL Concepts Used

### 1. JOIN Operations

Used to combine related information from multiple tables.

Examples:

* `Customer` with `Invoice`
* `Invoice` with `InvoiceLine`
* `Track` with `Genre`
* `Artist` with `Album` and `Track`

These joins connect customer purchases with music and revenue information.

### 2. Aggregate Functions

The project uses aggregate functions to summarize data.

| Function          | Purpose                                                     |
| ----------------- | ----------------------------------------------------------- |
| `SUM()`           | Calculate total spending, revenue, and purchased quantities |
| `COUNT()`         | Count purchases and records                                 |
| `COUNT(DISTINCT)` | Count unique genres purchased                               |
| `AVG()`           | Calculate average customer spending                         |
| `ROUND()`         | Round calculated values to two decimal places               |
| `MAX()`           | Find the latest purchase date                               |

### 3. GROUP BY and HAVING

* `GROUP BY` groups records by customer, country, artist, genre, track, or month.
* `HAVING` filters grouped results, such as customers spending above the average or purchasing from multiple genres.

### 4. Common Table Expressions (CTEs)

The `WITH` clause creates temporary named result sets.

CTEs are used for:

* Customer spending calculations
* Customer segmentation
* Ranking customers within each country
* Calculating cumulative revenue

### 5. Window Functions

The project uses window functions for advanced analysis.

| Function                   | Purpose                                                         |
| -------------------------- | --------------------------------------------------------------- |
| `RANK()`                   | Rank customers by spending within each country                  |
| `SUM() OVER()`             | Calculate revenue contribution and cumulative revenue           |
| `PARTITION BY`             | Create separate ranking groups for each country                 |
| `ORDER BY` inside `OVER()` | Define the order of ranking or cumulative calculations          |
| `ROWS UNBOUNDED PRECEDING` | Calculate a running total from the first row to the current row |

### 6. Subqueries

Subqueries are used to calculate average customer spending and compare individual customer spending against that average.

### 7. CASE Expression

The `CASE` expression categorizes customers based on total spending.

| Spending           | Customer Segment |
| ------------------ | ---------------- |
| 40 or more         | High Value       |
| 20 to less than 40 | Medium Value     |
| Below 20           | Low Value        |

These thresholds are the classification rules defined in this project.

### 8. Date and Time Functions

Date functions are used to analyze purchasing activity over time.

* `YEAR()` extracts the year from an invoice date.
* `MONTH()` extracts the month number.
* `DATE_FORMAT()` formats dates into `YYYY-MM` for monthly analysis.
* `MAX()` identifies the latest invoice date when analyzing recent purchases.
* `ORDER BY` sorts monthly revenue to identify the highest-revenue month.

### 9. Revenue Calculations

The project calculates customer revenue contribution using:

**Revenue Percentage**

`Customer Spending / Total Customer Spending × 100`

It also calculates cumulative revenue by adding customer spending in descending order of spending.

## 🔍 Key Findings and Insights

The queries are designed to reveal the following insights from the dataset:

1. **Customer value:** Total invoice spending identifies the highest-value customers and shows how spending differs across the customer base.

2. **Purchase frequency:** Counting invoices for each customer helps distinguish frequent purchasers from customers who purchase less often.

3. **Customer retention opportunities:** Comparing each customer's last purchase date with the latest invoice date helps identify customers who may need re-engagement.

4. **Music preferences:** Aggregating purchased quantities by genre and track reveals which music categories and tracks receive the most purchases.

5. **Revenue distribution:** Revenue calculations by artist, country, and customer help identify important contributors to overall sales.

6. **Customer segmentation:** Spending-based categories provide a simple way to group customers into high-, medium-, and low-value segments.

7. **Country-level customer rankings:** Window functions identify the highest-spending customers within each country.

8. **Cross-genre purchasing:** Counting distinct genres per customer identifies customers whose purchases span multiple music genres.

9. **Cumulative revenue:** A running total of customer spending shows how revenue accumulates when customers are ordered from highest to lowest spending.

10. **Monthly revenue trends:** Grouping invoice totals by month helps identify the month with the highest recorded revenue.

*Note: These are the analytical insights the queries are designed to investigate. Exact customer names, revenue amounts, rankings, and the highest-revenue month should be taken from the actual query results.*
